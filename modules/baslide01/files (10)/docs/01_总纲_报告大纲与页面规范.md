# 侍天 TIANSIGHT · 智能分析报告系统
## 卷一：报告大纲 · 页面规范 · D3 图元库

> **设计原则（贯穿全系统）**：**从「决策」倒推「页面」，不是从「数据」正推「图表」。**
> 每一页必须能回答一个具体的经营动作问题——「这 17 款到底砍不砍、砍哪 17 款」。
> 一页 = 一个决策 = 一张主图 + 一份全量名录 + 一条证伪条件。答不上「看完这页明天做什么」的页面，删掉。

**版本** v1.0 · 2026-08-11 ｜ **对应方法论** 《侍天 TIANSIGHT 分析体系 Part 1 v2.0》58 分析点
**目标形态** 客户交付原始数据 → 字段自动对齐 → 门禁自动判定 → 页面自动生成 → 结论自动落笔 → 争议点自动登记

# 第零部分　系统总架构

## 0.1 六阶段流水线

```
① 接入 INGEST      原始文件（CSV/XLSX/POS 导出）→ 表指纹识别 → 表角色判定
                     ↓
② 对齐 ALIGN        列名 × 值特征 双通道匹配 → 置信度打分 → 自动绑定/人工确认/未识别
                     ↓                                    ← ★ 这一层决定系统是否「智能」
③ 门禁 GATE         三路对账 + 五类质检 + 覆盖度扫描 → 输出「本次能出哪些页」清单
                     ↓                                    ← ★ 这一层决定结论是否「可信」
④ 计算 COMPUTE      口径 A / 口径 B 双轨指标层 → 58 分析点算子 → 中位数与分位基准
                     ↓
⑤ 渲染 RENDER       页面注册表驱动 → D3 图元 + 全量名录表 + 读法条 + 结论条
                     ↓
⑥ 收敛 CONVERGE     行动优先级矩阵 → 效益去重区间 → 争议点与证伪登记（A58 强制清单）
```

**关键判断**：市面上所有「智能分析」死在第 ② 层和第 ③ 层。
② 层做不好 → 客户每次都要手工映射 40 个字段，比自己做表还慢。
③ 层做不好 → 系统照样出图，但结论是错的（清水亭案例：不做对账，全部金额虚高 10.6%）。

# 第二部分　页面版式规范（8 种标准版式）

> 全部版式沿用现有幻灯片设计令牌：`--surface:#F4F0E7` / `--paper:#FFFDF8` / `--charcoal:#17130D` / `--gold:#76551F` / `--gold-hi:#D4A862` / `--seal:#8C3228`；正文 Noto Serif SC，数字 IBM Plex Mono（tabular-nums），标签 Noto Serif 大写字距 .34em。画布 1440×810。

| 代号 | 版式 | 结构 | 用于 |
|---|---|---|---|
| `cover` | 封面 / 章扉 | 竖排章号 + 章名 + 一句话核心决策 + 本章分析点代号带 | 14 页 |
| `viz-full` | 单图全幅 | 页眉 → 来源条 → **主图 72% 高** → 读法条 → 结论条 | 最常用，约 40 页 |
| `viz-table` | 图表左右分栏 | 左图 58% / 右表 42%，共享一条结论条 | 约 28 页 |
| `viz-duo` | 双图对照 | 上下或左右两图，中间加「因此」箭头 | 约 18 页 |
| `matrix-full` | 矩阵热力全幅 | 矩阵 + 双边际条形 + 判读纪律脚注 | 约 12 页 |
| `kpi-grid` | 指标卡阵 | 3×2 或 4×2 卡片，每卡：大数 + 标签 + 环比 + 迷你走势 | 约 8 页 |
| `roster` | 全量名录表 | 可排序表格 + 筛选 chip + 「合计校验行」（**行合计必须显示，兑现完整性纪律**） | 约 30 页 |
| `verdict` | 结论与证伪 | 争议点 / 事实 / 处理 / 证伪条件 四段栏，朱印状态章 | 约 10 页 |

## 每页必备的六个元素（缺一不可）

```
① 页眉 chip：分析点代号 · 口径(A/B) · 周期 · 数据期间
② 来源条 SOURCE：源文件 + 行数 + 计算式（一行写清分母）
③ 主图 / 主表
④ 读法条 HOW TO READ：这张图该怎么看（新手也能读懂）
⑤ 结论条 TAKEAWAY：一句可执行的话，含数字
⑥ 页脚：分母声明 + 降级水印（若有）+ 证伪条件编号
```

> **④ 读法条是本系统与普通 BI 的核心差异**。BI 给图，咨询给读法。自动化系统必须把读法也自动生成——每个图元在注册表里携带 `howToRead` 模板，由指标值填空。

## 六条渲染纪律（写进图元基类，不可绕过）

```
① 分母必须随图走：每个图元的 meta 强制携带 denominator 字段，渲染到来源条
② 中位线归高侧：所有阈值切分统一 ≥ 归高，图上以「≥」符号标注
③ 零值 ≠ 缺口：零值格只在基数达阈值时才标记为机会（避免制造伪洞察）
④ 样本不足画斜纹：n < 阈值的图形元素统一使用斜纹填充，不隐藏、不静默
⑤ 代理指标带水印：非标准口径指标（如元/桌/小时）自动加「禁止外部对标」页脚
⑥ 合计必须闭合：任何分类图，各部分之和必须等于全量，差额 > 0 时图元抛错拒绝渲染
```

# 第四部分　自动化的三个技术难点与解法

## 4.1 字段自动对齐（第 ② 层）

**双通道打分**：列名通道（别名词典 + 归一化 + 编辑距离）× 值特征通道（dtype / 基数 / 正则签名 / 数值分布），加权后取 top-3 候选。

| 置信度 | 处置 | 占比目标 |
|---|---|---:|
| ≥ 0.85 | 自动绑定 | ≥ 75% |
| 0.60–0.85 | 进人工裁定台（带候选与理由） | ≤ 20% |
| < 0.60 | 标记未识别，进缺口清单 | ≤ 5% |

**值特征签名示例**

```
会员手机号  → 11 位数字、以 1 开头、基数/行数 < 0.5
营业流水号  → 高基数（≈ 行数/8）、含字母数字混合、组内多行
小计金额    → 数值、两位小数、可被 单价×数量 校验
市别        → 枚举 ≤6、值域含「午/晚/夜」
主辅佐引    → 枚举 =4、值域 ⊂ {主,辅,佐,引}
```

## 4.2 跨口径防污染（第 ③④ 层）

指标层给每个数值打**口径标签**（A / B / 外部）与**分母标签**（开台数 72 天 / 堂食账单 30 天 / 会员笔数）。
运算符重载：不同标签的量相除 → **抛出 `BasisMismatchError`**，而不是静默出一个错数。这条直接对应方法论「六条禁止操作」。

## 4.3 结论自动落笔（第 ⑤⑥ 层）

结论条不用大模型自由生成，用**模板 + 阈值分支**：

```
A17 模板：
  「{流量品数} 款流量品以 {SKU占比} 的 SKU 数占 {额占比} 销售额——
   {if 额占比>50: 它才是收入主体，也是毛利优化的主战场
    else: 收入结构较分散，优先处理 {淘汰候选数} 款淘汰候选}」
```

自由生成只用于**争议点描述**（A58），且必须落入四段结构，并标记为「分析师判断，非数据直出」。

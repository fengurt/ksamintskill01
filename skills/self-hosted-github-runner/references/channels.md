# 跨境搬运通道：机制、前提、费用、坑

本文回答一个问题：一次发布的几百 MB 字节，怎样从境外 runner 到达境内生产主机，而不经过任何一台机器的跨境公网出口。

## 1. 对象存储跨地域复制（默认）

**机制。** 在境外地域建一个桶 A，在生产地域建一个桶 B，在 A 上配置「跨地域复制」规则，把指定前缀下新写入的对象异步复制到 B。复制由云厂商在自己的骨干网上完成，两端都是内网访问：runner 与 A 同地域，生产主机与 B 同地域。

**前提。**

- 两个桶都必须开启版本控制，这是所有三家云对复制的硬要求。
- 规则按前缀限定：只复制 `release-inbox/` 与 `release-outbox/`，避免把无关对象和费用带进来。
- 反向也配一条：B 的 `release-outbox/` 复制回 A，用来把生产结果带回境外，让 GitHub Deployment 状态由境外侧回写。
- 在控制台确认你的两个地域允许配对。腾讯 COS、阿里 OSS、华为 OBS 都支持跨境地域对，但个别地域组合可能受限；建桶前先在控制台的复制规则页面确认目标地域出现在下拉列表里。

**时延。** 复制是异步的，通常几分钟内到达；大对象和高峰期可能更久。代理靠 `.sig` 文件的出现判断完整性，所以不需要知道复制什么时候结束，只需要知道结束了没有。

**费用模型。** 跨地域复制按流出方地域的复制流量按 GB 计费；两端存储各自计费；同地域内网上传与下载免流量费，只收请求费。一次发布不到 1 GB，每月几十次发布的复制费用是个位数到几十元人民币量级。真正会失控的是忘记设生命周期，让每次发布的 tar 永久留在两个桶里。

**坑。**

- 删除默认不复制，这正好是你想要的：境外误删不会影响境内。清理靠各自的生命周期规则。
- 复制是最终一致的，`ListObjects` 可能先看到 manifest 再看到 tar。所以上传顺序必须是 tar 在前、签名在后，代理只认签名。
- 对象元数据里的自定义 header 会一起复制，但服务端加密配置是桶级别的，两个桶都要开。
- 桶名带 APPID，两个桶的桶名不同，内网端点域名也不同；模板里用变量，不要把境外桶名写进代理。

**内网端点。**

| 云 | 内网端点形式 | 说明 |
|---|---|---|
| 腾讯 COS | `<bucket>.cos-internal.<region>.tencentcos.cn`；旧域名 `cos.<region>.myqcloud.com` 在同地域 CVM 上也会解析到内网 | 用 `nslookup` 验证解析到 `169.254.x.x` 或 `10.x`，不要用 `ping` |
| 阿里 OSS | `<bucket>.oss-<region>-internal.aliyuncs.com` | ECS 同地域免流量 |
| 华为 OBS | `obs.<region>.myhuaweicloud.com`，在 VPC 内走内网 | 需要 VPC 终端节点或默认路由 |

**工具。** 优先 `rclone`：它把 COS、OSS、OBS 都当 S3 兼容端点，一份脚本三家云通用，且自带 `--checksum`、重试和限速。各家原生 CLI（`coscli`、`ossutil`、`obsutil`）也可以，但脚本就不通用了。

## 2. 镜像仓库企业版实例同步

**机制。** TCR 企业版、ACR 企业版都支持在两个实例之间配置同步规则：境外实例收到推送，云厂商把镜像层同步到境内实例；生产主机从境内实例内网拉取。这比对象存储更贴合 Docker 的工作方式，`docker push` 与 `docker pull` 不变。

**代价。** 企业版实例按小时或按月计费，两个实例是两份钱，对个人或小团队通常超过一台 runner 的成本。个人版（腾讯 `ccr.ccs.tencentyun.com`）没有实例同步能力。

**何时选。** 团队已经因为其他原因持有企业版实例；或者发布频率高到对象存储的 `docker save / load` 步骤成为瓶颈。

## 3. 境外直接推送到境内镜像仓库个人版

**机制。** 从境外 runner `docker push ccr.ccs.tencentyun.com/...`。流量走公网，但目标是云厂商自己的入口，通常比 ghcr 或 Docker Hub 的跨境链路好。

**必须实测。** 不同地域、不同时段差异极大。实测方法：

```bash
docker pull alpine:3.24.1
docker tag alpine:3.24.1 {{CN_REGISTRY}}/probe/alpine:test
time docker push {{CN_REGISTRY}}/probe/alpine:test          # 小镜像，测握手和延迟
docker build -t {{CN_REGISTRY}}/probe/big:test -f - . <<'EOF'
FROM alpine:3.24.1
RUN head -c 300M /dev/urandom > /blob
EOF
time docker push {{CN_REGISTRY}}/probe/big:test              # 300 MB 不可压缩层，测吞吐
```

连续三天、早晚各一次。中位数吞吐低于 2 MB/s 或出现任何一次超时，就不要把它当主通道。

## 4. 云联网 CCN 与专线

**机制。** 把境外 VPC 与境内 VPC 用云厂商私网连通，两边像一个内网。

**为什么不选。** 跨境带宽按 Mbps 包月，几 Mbps 的价格就超过一台 4 核 8G runner 的月费，而发布只需要搬几百 MB。这是为持续互访设计的产品，不是为发布设计的。

## 5. 境外 SSH / rsync 到境内主机

**只允许小控制流量，且本技能主张连控制流量也改为拉取。** 原因有二：一是跨境公网会让几百 MB 的 rsync 断在中途；二是境外机器持有生产 SSH 私钥违反铁律三，一次 PR 注入就能拿到生产。

## 6. 云厂商差异

| 项 | 腾讯云 | 阿里云 | 华为云 | AWS 中国 |
|---|---|---|---|---|
| 对象存储复制 | COS 跨地域复制 | OSS 跨区域复制 | OBS 跨区域复制 | S3 复制不能跨分区（中国分区与全球分区隔离） |
| 镜像仓库同步 | TCR 企业版实例同步；个人版无 | ACR 企业版同步 | SWR 镜像同步 | ECR 跨区域复制仅分区内 |
| GitHub Actions 免密凭据 | CAM OIDC 角色 | RAM OIDC 角色 | IAM 联邦身份 | 中国分区 OIDC 需单独配置 |
| 境外地域 | 香港、新加坡、东京、硅谷等 | 香港、新加坡等 | 香港、新加坡等 | 全球分区任一 |
| 本技能适配 | 直接套用 | 直接套用，改端点 | 直接套用，改端点 | 复制段需改为「境外 runner 用凭据写入中国分区 S3」，即公网上传，回到实测决定 |

## 7. 选择流程

1. 项目已有企业版镜像仓库实例且预算允许，选通道 2。
2. 否则建两个对象存储桶，选通道 1。这是默认路径，不需要额外购买任何产品。
3. 顺手做一次通道 3 的实测，记录数字。若吞吐稳定且高，可以把它作为清单里的第二镜像来源，但仍以通道 1 为准。
4. 通道 4 与 5 不进入方案。
